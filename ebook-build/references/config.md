# book.json — все поля

Все пути считаются от папки, где лежит `book.json`. Абсолютные пути работают, но ломают переносимость комплекта — не используй их.

Рабочий пример на реальной книге: `assets/book.example.json`.

## Обязательные

| Поле | Что это |
|---|---|
| `title` | Название книги |
| `author` | Автор. В FB2 первое слово идёт в имя, остальное в фамилию |
| `basename` | Имя файлов без расширения. Точки допустимы (`…_бета_2.0`) |

## Текст

| Поле | По умолчанию | Что это |
|---|---|---|
| `chapters_dir` | `.` | Папка с главами |
| `chapters` | — | Явный порядок глав (имена файлов). **Предпочтительно**: порядок не зависит от сортировки имён |
| `chapters_glob` | `*.md` | Если `chapters` не задан — все файлы по маске, по алфавиту |
| `source_file` | — | Вместо папки: один файл, главы разбиваются по строкам `# ` (id глав: `01`, `02`, …) |
| `final_line` | — | Финальная строка книги, напр. `КОНЕЦ ПЕРВОЙ КНИГИ`. В исходнике стоит как `**…**` в конце последней главы; в книге — отдельной строкой по центру. Проверка требует ровно одну |

Каждая глава — Markdown-файл с первой строкой `# Заголовок`. Поддерживается: абзацы через пустую строку, `*курсив*`, `**полужирный**`, `***полужирный курсив***`, отбивка сцены (`---`, `-----`, `***`, `* * *`, `⸻` — строка целиком), `## подзаголовок`, `### подзаголовок второго уровня`, `> цитата`, перенос строки внутри абзаца (стихи, письма). Отбивка, стоящая вплотную к строке прозы без пустой строки, всё равно становится отдельной. Всё остальное (списки, таблицы, картинки, сноски) не поддерживается — проверка поймает сырую разметку как утечку.

## Режимы: одна книга — две сборки

Читательская сборка и рабочая различаются служебными слоями, а не текстом: в бете нет авторских шапок, POV-пометок и рабочих номеров глав, в альфе всё это нужно. Вместо второго `book.json` — блок `modes`: он переопределяет любые поля верхнего уровня.

```json
"default_mode": "reader",
"modes": {
  "reader":  {"basename": "kniga_beta",  "formats": ["epub", "md"],
              "numbering": {"enabled": true}},
  "working": {"basename": "kniga_alpha", "formats": ["epub"],
              "service_markers": {"strip_blocks": []}}
}
```

Словари сливаются поглубже, остальное заменяется целиком. Сборка: `--mode reader`, либо `--all-modes` — все режимы подряд и общая проверка.

Проверка требует, чтобы **проза во всех режимах совпадала слово в слово**: расхождение означает, что правка попала в одну сборку и не попала в другую.

## Нумерация и названия глав

| Поле | Что это |
|---|---|
| `titles` | `{"13_chapter.md": "Глава 13. Публичное название"}` — заголовок для книги, не трогая H1 в файле. Сборка предупреждает о каждой замене: книга выйдет правильной, а автор, открыв исходник, увидит старое имя |
| `numbering.enabled` | Сквозной счёт глав по порядку чтения вместо рабочих слотов: «Глава 13В. День в деревне» на двадцать первом месте станет «Глава 21. День в деревне» |
| `numbering.pattern` | Что считается нумерованной главой. По умолчанию `^Глава\s+\d+[А-ЯЁA-Z]?\.\s*(?P<name>.+)$`. Заголовки, не подошедшие под шаблон (пролог, эпилоги, названия одним словом), остаются как есть и номера не получают |
| `numbering.template` | Формат заголовка, по умолчанию `Глава {n}. {name}` |
| `numbering.start` | С какого номера начинать, по умолчанию 1 |
| `title_subtitle` | `keep` (по умолчанию) или `merge`. При `merge` подзаголовок `## Облигации` сразу под `# ГЛАВА 20` уходит в заголовок («ГЛАВА 20. Облигации») и не повторяется в тексте. Голая нумерация сцен (`## I`) под это не попадает |

Если в начале файла несколько H1 подряд («# Книга 2 — §1.1.Д» / «# ПРЕДЛОЖЕНИЕ…»), заголовком становится последний, остальные отбрасываются с WARN. Предупреждение о замене из `titles` не выводится, если заголовки различаются только регистром, кавычками и знаками («ГЛАВА 13: «СКЛАДНИК»» и «Глава 13. Складник»).

Номер считается при каждой сборке, поэтому перестановка глав в `chapters` сама его пересчитывает — руками править нечего. Рабочие слоты при этом остаются в именах файлов и в режиме `working`.

## Плашки вместо ненаписанных глав

Элемент `chapters` может быть не именем файла, а записью:

```json
{"stub": "Глава 16. Переправа", "id": "16_stub", "progress": 15,
 "pov": "Анна / Пётр", "loc": "Река",
 "description": "Один абзац: что будет в главе.",
 "sources": "мастер-библия §1.1.Д"}
```

`stub` — заголовок (на него действуют `titles` и `numbering`), `id` — для `parts` и `fragments`, `progress` — насколько глава проработана в замысле, в процентах. На месте главы встаёт страница «Глава ещё не написана» с описанием. Проверка плашку прозой не считает и выводит WARN со списком плашек. В комплект плашка едет записью в `book.json`.

## Заметка над главой и «От автора»

| Поле | Что это |
|---|---|
| `chapter_notes.enabled` | Над каждой главой — служебная заметка: версия, статус, POV, локация. Обычно только в режиме `working` |
| `chapter_meta` | `{"09_chapter09.md": {"status": "первый черновик", "pov": "Анна", "loc": "Город", "version": "v0.1"}}`. Версия берётся из шапки файла (`Рабочая версия 0.2`, `версия 2.1`); ручная используется, только если в шапке её нет. При расхождении сборка выводит WARN, а на заметке стоит версия из файла |
| `foreword_file` / `foreword` | Страница «От автора» после аннотации: путь к md или текст. Первая строка `# …` — заголовок страницы. Подстановки: `{date}`, `{edition}`, `{written_count}`, `{stub_count}`, `{stub_titles}`, `{composition}` (состав по главам: проза или плашка с процентом) |

Заметки, плашки и «От автора» — служебные вставки: в ePub это `div.svc-*`, в FB2 — `cite id="svc-…"`, в md — комментарий `<!-- stub: … -->`. Проверка вырезает их до сверки прозы и утечек, а «От автора» проверяет отдельно: страница есть и в ней нет сырой разметки.

## Контрольные фразы

| Поле | Что это |
|---|---|
| `must_contain` | `["фраза", {"text": "Дитя. Запомни одну вещь", "chapter": "21_chapter21.md"}]`. Для каждой — FAIL, если её нет в исходнике («нет в исходнике») или она не дошла до формата («потеряна при сборке»). Во фрагменте фразы из глав за границей пропускаются |

## Структура

| Поле | Что это |
|---|---|
| `parts` | Список частей/актов: `{"label": "АКТ ПЕРВЫЙ", "name": "Начало", "chapters": [...]}`. Перед первой главой части встаёт шмуцтитул; в оглавлении глава вложена в часть. Главы вне частей (пролог) идут верхним уровнем. Для эпилога со своим шмуцтитулом — часть с `"name": ""` |

## Режим с садом

Сады на шмуцтитулах частей. По умолчанию выключен: спокойная сборка не смотрит на эти поля и совпадает с прежней байт в байт.

| Поле | Что это |
|---|---|
| `gardens` | `true` — собрать книгу с садами. Обычно ставится в режиме: `"modes": {"сад": {"gardens": true}}`. То же делает флаг `--gardens` у `build_book.py`, `verify_book.py` и `package_project.py`. По умолчанию `false` |
| `gardens_live` | `true` — живой сад: в режиме с садом скрипт шмуцтитула выращивает сад части под формат экрана читалки (тот же `seed`), картинка остаётся запаской. Флаг `--live` у `build_book.py`, `verify_book.py`, `package_project.py`. Только тема `flora`. По умолчанию `false` |
| `chapter_gardens` | Сады в главах (только в режиме с садом): `true` или `{"head": true, "initials": true, "tail": true, "seed_base": 100, "dir": "gardens/chapters", "seeds": {}}` — заставка, буквица, концовка; seed главы = `seed_base` + номер в `chapters`, `seeds` закрепляет seed за файлом главы. Картинки рисует `make_gardens.py` (node). Можно задать в режиме: `"modes": {"сад": {"gardens": true, "chapter_gardens": true}}` |
| `gardens_suffix` | Суффикс к `basename` и к именам фрагментов в садовой сборке, по умолчанию `_сад` — чтобы не перезаписать спокойную книгу. `""` — без суффикса (тогда разведи имена в режиме сам) |
| `parts[].garden` | Сад части: `{"image": "gardens/act1.png", "seed": 1}` или строкой — путь к готовой картинке. `seed` нужен `make_gardens.py` и живому саду. В режиме с садом картинка обязана существовать, иначе сборка останавливается. Часть без `garden` получает обычный шмуцтитул |
| `garden_generator` | Параметры `make_gardens.py` и живого сада: `ink`, `accent` (RRGGBB), `theme` (`flora`, `geometric`, `math`), `season`, `novisitors`. По умолчанию делфтский синий, `flora`, лето |
| `garden_layout` | Где стоит название на холсте сада, в мм: `canvas` [121, 201], `x`, `label_y`, `label_size`, `label_spacing`, `rule_y`, `rule_half`, `rule_color`, `name_y`, `name_size`, `name_opacity`. Значения по умолчанию рассчитаны на лист `make_gardens.py`; меняй, только если меняешь и геометрию листа |

В комплект сады едут в `инструменты/gardens/`, если картинки есть. В `book.json` комплекта остаются исходные `basename`, `gardens` и `gardens_live`: режим — это выбор сборки, а не свойство книги.

## Оформление и метаданные

| Поле | По умолчанию | Что это |
|---|---|---|
| `subtitle` | — | Подзаголовок на титуле («Книга первая») |
| `language` | `ru` | Код языка. Определяет и тексты служебных страниц (`ru`/`en`) |
| `series` | — | `{"name": "…", "index": 1}` — серия: ePub (calibre:series), FB2 (sequence), MOBI |
| `edition` | — | Редакция: «публичная бета 2.0». На титуле и в колофоне |
| `cover` | — | Обложка JPEG/PNG. Без неё — предупреждение |
| `annotation` | — | Аннотация списком абзацев |
| `annotation_file` | — | Или файл: берутся абзацы раздела `# Аннотация` (или весь файл) |
| `colophon` | — | Строки колофона; подстановки `{title} {subtitle} {author} {edition} {series} {date}` |
| `genres_fb2` | `prose_contemporary` | Жанры FB2 (`sf_space`, `sf_detective`, `detective`, `prose_classic`, `love_contemporary`, `child_tale`, `nonf_biography` …) |
| `texts` | по языку | Переопределение служебных надписей: `annotation`, `title_page`, `colophon`, `built`, `series_line`, `continued`, `fragment_label`, `fragment_title_suffix`, `fragment_end` |

## Выход

| Поле | По умолчанию | Что это |
|---|---|---|
| `output_dir` | `books` | Куда класть готовые книги |
| `formats` | `["epub","fb2","mobi"]` | Форматы полной книги. MOBI требует Calibre. `md` — книга одним файлом Markdown |
| `fragments` | `[]` | Ознакомительные фрагменты, см. ниже |

Фрагмент:

```json
{"until": "13_chapter13.md", "basename": "…_фрагмент_главы_1-13",
 "range_label": "пролог и главы 1–13", "formats": ["epub"],
 "continuation": ["На этом фрагмент заканчивается.", "…", "Остальное — в полной книге."]}
```

`until` — последняя включаемая глава (id). Оборванная часть сохраняет шмуцтитул. У фрагмента своё название в метаданных («— фрагмент») и свой идентификатор, чтобы читалка не смешала его с полной книгой. `continuation` — страница «Продолжение следует»: напиши её под конкретную точку обрыва, не шаблоном.

## Markdown

Формат `md` в `formats` даёт книгу одним файлом: тот же текст, та же очистка и тот же порядок, что в ePub. Нужен для работы с иллюстрациями и для промптинга — в контекст модели удобнее класть текст, а не распакованный ePub.

| Поле | Что это |
|---|---|
| `md.illustrations` | Под заголовком каждой главы ставится якорь `<!-- ill: id | название | [промпт] -->`. При рендере не виден, грепом ищется; в квадратные скобки пишется промпт |
| `md.split` | Рядом кладётся папка `<basename>_chapters` — по файлу на главу, с номером и слотом в имени |

Перед каждой главой стоит якорь `<!-- ch: id | название | часть | N слов -->`. По нему же работает проверка, поэтому не удаляй его при правках. Проверка сверяет число слов в md с исходниками строго, с допуском в один процент: служебных страниц здесь нет, и расхождение означает потерю текста.

## Служебное

| Поле | Что это |
|---|---|
| `service_markers.strip_blocks` | Регулярки, вырезаемые в любом месте главы. По умолчанию: `*(версия …)*`, `*(монтаж …)*`, `*(version …)*`, `<!-- … -->`, абзац-шапка `*(Книга N «…». …)*` и он же без скобок. **Задание поля заменяет дефолты целиком** — для добавления есть `extra_blocks` |
| `service_markers.strip_trailing` | Пометки в конце главы — все подряд стоящие, каждая целой строкой. По умолчанию: `**КОНЕЦ ГЛАВЫ N**` и без звёздочек, `*КОНЕЦ ГЛАВЫ*`, `*[Конец гл. N, vX]*`, `*(Конец главы.)*`, то же для пролога, эпилога и части. Висящая отбивка в конце главы снимается вместе с ними |
| `service_markers.cut_from` | Строка, с которой файл обрезается до конца. По умолчанию `## Заметки редактора…` |
| `service_markers.extra_blocks` / `extra_trailing` / `extra_cut_from` | Добавляются к дефолтам. Для частных пометок книги используй их, а не замену списков |
| `service_markers.bare_sections` | Голая нумерация сцен внутри главы — `## I`, `## IV.`, `## 3`. По умолчанию `true`: такие строки **заменяются отбивкой**, а не удаляются, иначе сцены склеиваются. Если цифра стоит первой строкой главы, отбивка не ставится. Можно задать свою регулярку или `false` |
| `leak_patterns` | Дополнительные регулярки, которых не должно быть в готовой книге. Добавляются к стандартным: служебные слова («КОНЕЦ ГЛАВЫ», «[Конец гл.», «Рабочая версия», «(Книга N «», `POV`, `§N`, «по архитектуре v», «Заметки редактора»), `**`, `#` в любом месте абзаца, видимое `---`, `![`, `](`, `<!--`, TODO. В формате `md` разметка — это формат, а не утечка, поэтому там проверяются только служебные пометки |
| `leak_ignore` | Стандартные шаблоны утечек, законные для этой книги, — точной строкой из списка выше (например, `\\bPOV\\b`, если слово есть в прозе) |

Если автор завёл новую служебную пометку — добавь её и в `strip_*`, и в `leak_patterns`. Проверка должна ловить то, что сборка обязана вырезать.

## Комплект

| Поле | Что это |
|---|---|
| `package.name` | Имя папки комплекта |
